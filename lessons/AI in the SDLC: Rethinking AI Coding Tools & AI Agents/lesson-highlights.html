Redesigning the Software Development Lifecycle Around AI

Understand why AI coding tools alone don't speed up delivery, and how to apply AI across the whole SDLC instead of just the coding step.

What matters

  • Feeling faster is not the same as being faster: a controlled study found developers who believed AI made them 20% faster were actually about 20% slower.
  • Delivery time is dominated by waiting between teams and phases, not by typing code, so speeding up coding alone barely moves total delivery time.
  • Over-delegation - handing a model one huge ambiguous task - pushes unstated design decisions into the model and creates large unreviewed diffs that stall the review phase.
  • Under-delegation - using AI only for isolated, narrow tasks - produces good code but leaves the most time-consuming work, planning and architecture, entirely manual.
  • Spec-driven development replaces vague 'vibe coding' with a written specification a model can follow, executed by a harness of coordinated subagents.
  • AI has high-impact uses outside of coding: synthesizing requirements from user feedback, generating tests from user stories, diagnosing incidents from logs, writing infrastructure as code, and explaining legacy systems.
  • Real productivity gains come from redesigning the lifecycle around AI - shifting the human role from typing code to validating it and coordinating across teams - not from picking a better model.
  • The right metrics for AI-assisted delivery are outcomes (system health, maintainability, time to ship a change), not lines of code generated.

Glossary

Software development lifecycle (SDLC)
The sequence of stages a team moves through to deliver software: requirements, design, build (code and test), release, and operate.
Model evaluation and threat research organization
The kind of organization referenced in the video's study - one that runs controlled evaluations of AI systems, including measuring real-world productivity effects rather than relying on self-reported estimates.
Over-delegation
Handing a model one large, ambiguous task and expecting it to complete the work autonomously, which pushes unstated design decisions into unreviewed code.
Under-delegation
Using AI only for narrow, well-scoped tasks while a human still does all the planning and architecture, which caps how much of the total work AI can speed up.
Vibe coding
Generating code from a rough, evolving prompt and iterating loosely until it feels right, without a written specification of what's actually required.
Spec-driven development
Turning the intent behind a feature into a written specification precise enough for a model to read and follow, then breaking the work into small, well-defined tasks.
Harness
The full system around an AI agent - the underlying model plus the tools, memory, and orchestration logic it can use - not just the model itself.
Subagent
A smaller agent given a narrow, specific job (e.g. research, code editing) within a larger multi-agent workflow coordinated by a harness.
MCP (Model Context Protocol)
A protocol that lets an AI agent connect to external servers to pull in data or capabilities from other systems a team relies on.
AGENTS.md
A shared file that documents context, conventions, and instructions for AI agents working across a team or organization, so different agents and people stay consistent.
Infrastructure as code (IaC)
Defining infrastructure - servers, containers, deployments - through machine-readable configuration files, such as Ansible playbooks or Kubernetes YAML, instead of manual setup steps.
Skills
Packaged, reusable instructions that help an AI system produce consistent output for a given task regardless of which underlying model is running it.
